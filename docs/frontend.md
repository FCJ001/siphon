## 0. 技术栈：对齐 a-share-research-os，不引第二套工具链

现项目已验证的栈，直接复用：

| 项 | 选型 | 理由 |
|---|---|---|
| 构建 | **无构建步骤** | 现项目零 package.json、零 vite；中转站后台不值得引一套构建链 |
| 框架 | **原生 HTML/CSS/JS** | 现项目 7 个 `app-*.js` 共 1.37 万行，无框架也扛住了 |
| 模块拆分 | 按功能拆 `app-N-<domain>.js` | 沿用现项目惯例（core/ledger/activity/library/verify/today/ops） |
| 图表 | **手写 SVG** | 现项目已验证：无 canvas、无图表库，4 个模块里都是内联 SVG |
| 主题 | `data-theme` on `<html>` + localStorage + 防闪烁内联脚本 | 现项目同款，深浅色双主题 |
| 缓存击穿 | `?v=YYYYMMDDx` 查询串 | 现项目同款 |
| 设计流程 | `design/*.html` 出稿 → `scripts/shot-*.cjs` 截图 → 定稿 → 落 `src/static/` | 现项目 71 个 HTML 稿 + 279 张 PNG 的工作流 |
| 鉴权 | 独立 `login.html` | 现项目同款；管理后台必须鉴权 |

API 服务用同一个 FastAPI 进程挂载 `StaticFiles`，不要拆成两个服务。

## 1. 信息架构

后台类产品的判断标准：**一眼看清"钱花在哪、省了多少、哪里出问题"**。

| # | 页面 | 回答的问题 | 优先级 |
|---|---|---|---|
| 1 | **总览** | 今天/本月花了多少、省了多少、现在健康吗 | P0 |
| 2 | **账号管理** | 账号怎么配、每把 key 还剩多少、熔断没有 | P0 |
| 3 | **日志** | 每一笔请求具体长什么样、优化器有没有生效 | P0 |
| 4 | **路由与优化器** | 优化策略怎么配、改了立刻生效吗 | P1 |
| 5 | **分析** | 趋势如何、成本结构变了吗 | P1 |
| 6 | **令牌** | 对外发的 key 谁在用、用了多少 | P2 |
| 7 | **告警** | 出过什么事、规则怎么配 | P2 |

**与 one-api / new-api 那类后台的区别**：那些是"渠道 + 令牌 + 计费"三件套。
本站的灵魂是 **省钱可视化 + 优化器控制**，所以第 1 页和第 4 页是重点，其余是对标。

## 2. 总览页（首屏，最重要）

### 2.1 顶部 KPI 四联

```
┌──────────────┬──────────────┬──────────────┬──────────────┐
│ 本月实际成本  │ 本月已节省    │ 缓存命中率    │ 请求数        │
│ $8.5         │ $23.5 (73%)  │ 91.2%        │ 62,140       │
│ 等效 30M tok │ 等效 170M tok│ ↑0.8pp 较昨日 │ 失败率 0.3%   │
└──────────────┴──────────────┴──────────────┴──────────────┘
```

"已节省"必须**可拆解**，否则用户不信。对应下面的瀑布图。

### 2.2 节省归因瀑布图（本页主角）

横向瀑布，把"基线 → 实际"的每一段节省拆开，这是数据中心里最重要的一个组件：

```
基线(无缓存无优化)  ████████████████████████████████  $32.0
  − 上游前缀缓存                              ████████ −$19.5
  − 分轮次 effort 控制                        ███ −$3.3
  − 工具结果规范化                            █ −$0.4
  − 精确响应回放                              █ −$0.4
  − 免费档路由                                █ −$0.4
实际成本                                                    $8.5
```

- 每段标注：金额 + 等效 token 数
- 悬停显示该优化器的定义与生效参数（从路由配置页同一份数据取，避免两处口径不一致）
- 数据源：后端 `GET /api/analytics/savings-attribution?range=`

**这个组件是中转站的销售凭证。** 没有它，用户无法判断优化器是否真的在工作。

### 2.3 账号水位(签名元素: 三窗水位计)

每个账号一张仪表卡, 三支竖直水位管对应三个配额窗口(5h / 周 / 月) ——
OpenCode Go 的配额窗口天然是"水位": 会排空与回灌, 所以管内液面 = 窗口已用百分比:

```
主力 …bbbb  [主力]                备用 …dddd
5H        周        月            5H        周        月
▓▓        ▓▓        ▓▓            ▓▓        ▓▓(红)    ▓▓
12%       34%       21%           46%       87%       62%
在途 0/24 · 权重 100 · 5h 回灌 1小时48分后
```

- 液面配色: <70% 水色 · 70–85% 黄铜 · ≥85% 朱红; 管壁 85% 处刻警戒虚线(始终可见, z 轴在液面之上)
- 液面高度有 0.8s 填充动画(prefers-reduced-motion 时静止)
- 点击卡片跳账号页详情
- 数据源: `/api/accounts` 的 `windows` 字段(轮询 /usage 回填, 重启从 quota_snapshots 快照恢复)

账号管理页的表格行内嵌**迷你三窗水位管**(34px), 不占额外空间。

### 2.4 实时请求流

SSE 推送的最近 N 条请求，滚动列表，每条一行：

```
09:55:51  deepseek-v4.1-flash  账号1  in 6.8k(cache 6.2k) out 412  effort high→low  1.2s
09:55:52  deepseek-v4-flash    账号1  in 4.1k(cache 3.9k) out 118  effort low        0.6s  ↩replay
```

`effort high→low` 和 `↩replay` 是高亮项 —— 让优化器的工作**可见**。

### 2.5 模型分布

按调用数与成本两个口径的横向条形图。成本口径下要能看出"哪个模型在吃钱"。

## 3. 账号管理页（配置中心）

这一页是**配置中心**，不只是状态面板。账号的增删改、路由参数、熔断参数、全局策略全部在这里。

### 3.0 页面结构

```
┌─ 工具栏 ──────────────────────────────────────────────────────┐
│ [+ 添加账号] [批量导入] [批量启用/禁用] [导出配置] [导入配置]     │
│ 筛选: 状态 ▾  额度使用率 ▾   排序: 优先级 ▾                    │
├─ 账号列表 ───────────────────────────────────────────────────┤
│  别名/尾号      状态    主力  权重  在途   5h/周/月   操作      │
│  主力 sk-LptL   ●正常   ✓    100   3/24   0/0/0     [编辑]…   │
│  备用 sk-Q5yZ   ⚠降权        50    0/24   0/84/73   [编辑]…   │
├─ 全局账号策略 ────────────────────────────────────────────────┤
│  主力账号 / 溢出策略 / 粘性 TTL / 默认熔断参数                  │
└───────────────────────────────────────────────────────────────┘
```

点击任一行 → 右侧抽屉展开账号详情（不跳页，保持列表上下文）。

### 3.1 账号列表

列：别名 + key 尾号 · 状态徽标 · 是否主力 · 权重 · 在途/上限 · 三窗口百分比 · 最近错误 · 操作。

- 状态徽标四态：`● 正常` / `⚠ 降权`（接近上限） / `⛔ 熔断`（附剩余冷却倒计时） / `○ 已禁用`
- 低于 70% 正常色、70–85% 警示色、≥85% 危险色、≥100% 熔断色
- 筛选：状态、额度使用率区间
- 批量选择后：启用 / 禁用 / 导出

### 3.2 添加 / 编辑账号（表单，按分组折叠）

| 分组 | 字段 | 说明 |
|---|---|---|
| **基础** | API Key | 密码框；粘贴后只显示尾号。**编辑时留空 = 不修改** |
| | 别名 | 展示用，如「主力」「备用」 |
| | 备注 | 自由文本 |
| **路由** | 设为主力 | 单选，全站同一时间只能一个 |
| | 权重 | 1–100，参与打分路由；0 = 不参与新会话分配（仅保粘性） |
| | 模型白名单 | 多选；空 = 允许全部模型 |
| | 在途上限 | 该账号并发请求上限，超出则排队或溢出 |
| **熔断** | 失败阈值 | 模型级 / 账号级分开设，默认继承全局 |
| | 冷却时长 | 同上 |
| **高级** | 每模型月度上限 | 默认取全局 `LLM_MODEL_MONTHLY_CAP_USD`；此处可覆盖，供本地账本校准 |
| | 自定义 session | 默认自动生成；提供「重置」按钮 |
| | 代理 | 可选，独立于全局 |

**保存前行为**（这一条很重要，避免落库一堆废 key）：

1. 自动试调一次 `GET /usage` 校验 key
2. 失败时给出明确归因：`401` → key 无效；超时 → 网络；`429` → key 有效但已超限（允许保存）
3. 提供「仍然保存并标记为异常」的逃生口
4. 编辑权重 / 白名单时，右侧实时显示**影响预览**：当前路由分布会怎么变

### 3.3 账号详情（抽屉）

- **配额三窗口**：进度条 + `resetsAt` 倒计时（人话格式：「4 小时 12 分后」）
- **模型级消耗**：本地上限 vs 已用，按模型分列
- **熔断历史**：时间线，含触发原因（模型级 / 账号级）、持续时长
- **近期请求与错误**：复用日志页的表格组件，预置该账号的筛选
- **操作**：重置熔断 · 重置 session · 测试连通性 · 禁用 · 删除

两个口径必须分开标注，**不要混在一张表里**：
- 窗口百分比来自上游 `/usage`（账号级）
- 模型级消耗来自本地累加（上游不提供）

熔断状态同样要区分模型级与账号级（见 [design.md](./design.md) §4.3），恢复时间不同。

### 3.4 全局账号策略

| 项 | 默认 | 说明 |
|---|---|---|
| 主力账号 | 账号1 | 低流量时优先走它 |
| 溢出策略 | **严格粘性** | 严格粘性 = 宁可在途排队也不换账号（保护缓存）；允许溢出 = 打满就切 |
| 会话粘性 TTL | 3600s | 同一会话钉在同一账号的时长 |
| 默认熔断参数 | 模型级 15min / 账号级至 reset | 新账号继承 |
| 免费档路由 | 开 | 是否允许把杂活导向免费模型 |

### 3.5 交互约定

- **Key 明文只在创建时显示一次**，之后任何界面都只显示尾号
- 危险操作二次确认：删除账号、禁用主力、重置 session、批量禁用
- 所有配置变更写入**审计日志**，可查"谁在什么时候把什么从 A 改成了 B"
- 保存即热加载，不需要重启服务；页面顶部显示"最近生效时间"
- 支持 **JSON 导入导出**，用于迁移和备份（导出时可选择是否含 key 明文）

## 4. 路由与优化器页

这一页是本站的差异化，本质是**一份热加载的配置表单**。

### 4.1 档位映射

| 档位 | 模型 | effort |
|---|---|---|
| strong | deepseek-v4.1-flash | max |
| mid | deepseek-v4-flash | low |
| cheap | mimo-v2.5 | max |

### 4.2 优化器开关与参数

| 优化器 | 开关 | 参数 |
|---|---|---|
| 分轮次 effort 控制 | ✅ | 首轮 → `low`；工具轮数 < `4` → `medium`；尾声轮不降 |
| 工具结果规范化 | ✅ | K 线保留根数 `20`；生效工具白名单 |
| 精确响应回放 | ✅ | TTL `180s`；temperature 上限 `0.1` |
| 免费档路由 | ✅ | 触发条件：无 tools / prompt < `2k` / temperature ≤ `0.1` |
| 会话粘性 | ✅（强制） | 亲和 TTL `3600s` |

### 4.3 前缀不变式守卫（只读展示）

后端如果检测到请求会破坏缓存（如 tools 顺序变化、动态增删工具），应当拒绝改写并记一条事件。
本页只读展示最近 N 条这类事件 —— **这是给未来的自己看的护栏**。

### 4.4 生效机制

- 保存即热加载，页面顶部显示"最近生效时间"
- 每个配置项显示"改为当前值会怎样"的一句话说明（例如：把阈值 4 改成 6 会更保守、省得更少但更稳）
- 提供"回滚到上一版"（配置存历史版本）

## 6. 分析页

图表规格见 §7（图表 1、2、6、7、9、10、11 落在这页）。本节只讲页面本身的交互。

**统一的控制条**（所有图表联动，一次切换全页生效）：

| 控件 | 取值 |
|---|---|
| 时间范围 | 今日 / 7 日 / 30 日 / 自定义 |
| 时间粒度 | 小时 / 日（30 日范围时自动切日并禁用小时） |
| 维度 | 按模型 / 按账号 / 按令牌 / 不分组 |
| 口径 | token 数 / 等效成本 / 请求数 |

**三条阅读路径**（页面按这个顺序排布，不要打乱）：

1. **量在哪** —— 用量趋势（堆叠三段）→ 模型分布
2. **有没有退化** —— 缓存命中率趋势（带目标线）→ 输出占比趋势
3. **哪里可以再压** —— 工具 token 排行 → 请求耗时分布 → 配额热力图

每张图右上角挂一个「？」按钮，点开写明：这张图在什么情况下该警惕、对应去哪个页面处理。
例如缓存命中率图的说明是：「连续 2 小时低于 70% → 去日志页筛 `cached=false`，
检查是否有会话在跨账号漂移」。

**联动下钻**：点击图表任一数据点 → 跳日志页并带上对应筛选条件（如点某个模型的成本柱 →
日志页筛该模型）。分析页的终点永远是日志页的原始请求。

### 7.1 图表清单

**第 1、6、7 三张是"用量能不能看"的核心**：分别回答「量花在哪」「缓存还好吗」「成本重心有没有跑偏」。

### 7.2 图表基元（先建 `app-0-chart.js`）

手写 SVG 不等于每次从零画。先做 7 个基元，各页面组合调用：

| 基元 | 覆盖上面哪些图 |
|---|---|
| `line(opts)` 折线 + 可选面积 + 多序列 + 堆叠 | 1, 2, 5, 6, 7, 12 |
| `bar(opts)` 横/纵 + 堆叠 + 分组 | 8, 9 |
| `waterfall(opts)` 瀑布 | 3 |
| `donut(opts)` 环形进度 | 4 |
| `heat(opts)` 热力格 | 11 |
| `hist(opts)` 直方图 | 10 |
| `axis(opts)` 坐标轴 / 网格 / 图例（被上面复用） | 全部 |

统一入参 `{el, data, x, y, series, theme, onHover}`，统一返回 `{update(data), destroy()}` ——
所有图表支持原地更新，避免每次刷新都重建 DOM。

### 7.3 手写 SVG 的六个坑

1. **节点数**：SVG 超过约 2000 个节点开始明显卡顿。数据点多时必须降采样（分桶取极值或 LTTB），
   且用**单条 `<path>` 拼接**而非逐点 `<circle>`。
2. **响应式**：靠 `viewBox` + `preserveAspectRatio` 让 CSS 控制尺寸，
   **不要**监听 resize 重算坐标；重算只发生在数据变化时。
3. **Tooltip**：一个单例绝对定位 DOM 节点 + 容器级 `mousemove` 命中检测，
   不要给每个数据点绑事件。
4. **暗色主题**：颜色一律走 CSS 变量（`var(--chart-1)` …），不要写死在 JS 里 ——
   否则切主题要重画全部图表。现项目的 `data-theme` 机制可直接承接。
5. **空态**：无数据时显示占位文案，不要留一个空坐标系。
6. **时间轴标签**：按容器宽度抽样显示，不要全画。

### 7.4 三个必须有的标注

- **目标线**：缓存命中率图上画一条目标线（如 85%），低于目标时线变警示色 ——
  这是判断"缓存是否在退化"的唯一视觉信号
- **预测外推**：配额图用虚线外推「按当前速率，X 小时后耗尽」，比只显示已用百分比有用得多
- **事件标记**：趋势图上叠加熔断 / 429 事件的竖线标记，让"用量异常"和"事故"能对上时间

### 7.5 后端配合

## 8. 实时数据方案

- 单条 SSE 连接 `/api/events/stream`，事件带 `topic` 字段：
  - `quota` — 配额快照变化（每 5 分钟 / 每次 /usage 轮询后）
  - `request` — 完成的请求摘要（用于实时流）
  - `breaker` — 熔断开/关
  - `config` — 配置热加载生效
- 前端一个 `EventSource`，按当前页面订阅 topic，切页不断连
- 断线重连（指数退避）+ 三条失败后降级为 30s 轮询，并在顶栏显示"实时已断开"
